# Feature 1 UI Redesign Checklist Pass

Date: 2026-04-23

Scope: Feature 1 shell and workflow polish only. This pass does not add reader functionality, discovery features, or broader product expansion.

Reference basis used for this audit:
- Folo for premium shell quality, clear product framing, and dense feed-oriented browsing surfaces
- Feeder for direct navigation, approachable dashboard clarity, and efficient scanning
- RSS.app for polished feed cards, crisp control hierarchy, and responsive widget-style presentation

## Where RSSHubVite Falls Short

- The current shell still reads more like a capable internal tool than a finished product workspace.
- Primary workflow and secondary tools are functional, but the navigation model is too light to communicate a strong app structure.
- The saved-feed library is useful, but it is not compact or scannable enough to feel like a reusable feed hub.
- The live-feed view works, but its layout is closer to a preview panel than a polished browse surface.
- The interface uses too many pills and equally-weighted panels, which softens hierarchy and makes density feel lower than the reference set.

## Must Fix For Feature 1 Polish

- Replace the icon-only utility rail with a clearer workspace navigation shell that makes each mode feel intentional.
- Strengthen product chrome so the app feels like a cohesive workspace instead of a stack of large cards under a hero header.
- Tighten the saved-feed library into a denser, more reusable feed hub with stronger title, route, URL, and action hierarchy.
- Upgrade the live-feed surface into a stronger browsing view with clearer feed context, tighter item cards, and better action placement.
- Reduce visual noise from chips, metadata, and oversized spacing where it weakens the primary route-to-feed workflow.

## Should Fix

- Tighten search-result density so more route context is visible without making the list noisy.
- Reduce duplicate explanatory copy between shell-level framing and local panel headers.
- Improve how active filters and current route context are surfaced across sections.
- Make mobile and narrow-width navigation feel more like a deliberate product pattern and less like a compressed desktop layout.
- Revisit a few low-signal decorative surfaces so the strongest actions and content remain the visual anchors.

## Future Redesign Ideas

- Add richer library organization such as sort modes, grouping, or pinned feeds.
- Add a split workflow mode where route setup and live-feed browsing can coexist in a more dashboard-like layout.
- Explore deeper brand differentiation for illustration, motion, and empty-state storytelling.
- Rework the route search surface into a more advanced command-style launcher once Feature 2 and Feature 3 settle the broader product IA.
